# K-gov-agent 구현 계획

2026-11-21 (Asia/Seoul) 갱신.

현재 PoC는 Cloudflare Access의 Google 로그인으로 계정을 자동 생성하고 관리자가 사용을 승인한다. 계정별 대화·파일 소유권을 유지한다. [인증·승인 기준](AUTH.md)

## 목적과 출발점

목표는 공공부문 기관 직원이 각 기관의 내부망에서 업무를 맡기고, 실행에 개입하며, 결과물을 검토·수정하는 업무 공간을 만드는 것이다. 기관별 독립 배포를 전제로 공통 업무 흐름과 기관별 연결 지점을 설계한다. [제품 방향](PRODUCT_DIRECTION.md)

현재 OCI·Cloudflare 배포는 개발 시연에 사용한다. 기존 개인용 서비스 종료와 보존 경위는 [배포 안내](DEPLOYMENT.md)에 기록한다.

## 제안 업무와 범위

파일럿 기관의 업무 담당자 인터뷰 후 첫 평가 사례를 확정한다. 첫 자료 세트는 대표 문서 30~50개, 평가 질문 50개를 제안한다.

| 업무 | 요청 예시 | 결과 |
| --- | --- | --- |
| 내부 규정·매뉴얼 질의 | 업무 처리 절차와 필요한 서류 | 절차 설명, 근거 문서·페이지·조항 |
| 문서 비교·검토 | 첨부 초안과 지침의 차이 확인 | 누락·차이점, 각 판단의 근거 |
| 업무 초안 작성 | 제공 자료로 검토보고서 작성 | 지정 양식의 초안, 참고 자료, 확인할 사항 |

흐름은 검색 → 원문 확인 → 비교·정리 → 결과 작성이다. 전자결재 상신, 메일 발송, 업무시스템 데이터 변경은 후속 범위로 두고 실행 전 검토·승인을 적용한다. 개인 대화를 자동으로 장기기억에 저장하는 기능도 초기 범위에서 제외한다.

## 목표 구성

```text
직원용 웹 → 인증·권한 → 업무 에이전트 → 허용된 업무 도구
                            ├─ 내부 문서 검색·원문 조회
                            ├─ 첨부 자료 비교·분석
                            └─ 업무 초안 작성
                                 ↓
                      실행 worker / 대화·작업 DB / 파일 저장소

문서 등록 → 추출·OCR → 분할·색인 → 권한 기반 검색
모델 연결 계층 → 허용된 LLM·임베딩 모델
```

목표 기술 후보는 Next.js, FastAPI, PostgreSQL과 벡터 검색이다. 에이전트 프레임워크는 도구 호출과 실행 제어를 작은 사례로 검증한 뒤 확정한다. 여러 에이전트로의 분할은 필요성이 확인됐을 때 도입한다.

첫 기반 구현은 로컬 SQLite와 같은 origin의 정적 웹으로 인증·권한 규칙을 먼저 검증한다. 이는 운영 구성의 완료를 뜻하지 않는다. 파일도 작은 합성 자료만 DB BLOB으로 저장하며, 문서 처리 단계에서 파일 저장소와 수명 관리를 분리한다. 운영 전 PostgreSQL·마이그레이션·실제 인증·HTTPS를 구현하고 다시 검증한다.

## 데이터와 권한 원칙

- 서버가 인증된 신원으로 사용자 ID와 역할을 결정한다. 업무 API는 승인 상태와 리소스 소유권을 검사한다.
- 대화·메시지는 본인만 접근한다. 관리자는 계정 관리 권한만 가지며 업무내용 열람 권한을 자동 부여받지 않는다.
- PoC에서 파일과 프로젝트는 소유자만 접근한다. 기관 내부 자료 검색을 추가할 때는 기관이 부여한 자료 접근 권한을 적용한다.
- 기관별 배포 경계에 업무 데이터, 검색 색인, 백업, 감사 기록을 둔다. 보관 기간과 복원 절차는 기관 운영 기준에 맞춘다.
- 검색 후보를 만들기 전에 권한을 적용한다. 문서 원문·청크·벡터·검색 결과·캐시·생성 파일에도 같은 경계를 유지한다.
- 문서명, 버전·시행일, 페이지·조항, 근거 구절을 보존한다. 검색 성공과 답변의 근거 충실성을 별도로 평가한다.
- 개정·삭제 시 색인·파생물·캐시에도 반영한다. 근거 부족이나 충돌은 사용자에게 확인 대상으로 표시한다.
- 문서·도구 결과 안의 지시로 권한을 변경하지 않는다. 권한은 프롬프트가 아닌 서버 도구에서 검사한다.
- 로그와 감사 이벤트에는 대화·파일 원문, 비밀번호, 세션 토큰을 기록하지 않는다. 감사 기록의 보관 기간은 파일럿 전에 확정한다.

PostgreSQL 전환 시 앱 권한 검사에 더해 RLS를 검토한다. RLS 적용 시 테이블 소유자·관리자 계정의 우회 가능성과 커넥션 풀의 사용자 컨텍스트 격리를 검증한다. [PostgreSQL 공식 문서](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

## 환경별 진행

| 항목 | 개발·시연 | 기관 내부망 파일럿 |
| --- | --- | --- |
| 자료 | 공개·합성·비식별 샘플 | 사용 범위가 정해진 내부 자료 |
| 사용자 | 로컬 합성 계정 또는 시연용 Access와 관리자 승인 | 기관 인증과 승인된 파일럿 사용자 |
| 모델 | 허용된 개발용 모델 | 내부 사용 조건을 충족하는 모델 |
| 업무시스템 | 파일 업로드·모의 데이터 | 선정 시스템의 읽기 연동부터 |

기관별로 망 구성, 외부 통신 허용 범위, IdP, 모델·저장소 환경, 대상 업무시스템을 확인한다. 공통 코드를 유지한 채 설정과 어댑터로 차이를 반영한다. 모델을 교체하면 한국어 답변·검색·도구 호출 성능을 다시 평가한다.

## 구현 단계와 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 0. 범위 확정 | 파일럿 기관·업무 3개·자료·평가 질문 선정 | 성공 판단 기준 및 자료 사용 범위 확정 |
| 1. 다중 사용자 기반 | 인증·승인·역할, 대화·파일 격리, 관리·감사 | 교차 사용자 접근 차단, 로그인·정지·재접속 검증 |
| 2. Work 경험 기반 | Work 형태 UI, 실제 모델 대화, 스트리밍, 중지·오류 | 자연어 요청과 실제 답변, 권한 격리 유지 |
| 3. 작업 실행·결과물 | worker·재접속 복원, 첨부 분석·파일 생성·미리보기 | 업무 요청에서 검토 가능한 결과물까지 완수 |
| 4. 개입·프로젝트·연동 | 방향 수정·질문·승인, 결과 버전, 프로젝트, 권한 검색·도구·반복 업무 | 같은 맥락에서 수정·후속·반복 업무 수행 |
| 5. 기관 내부망 파일럿·품질 검증 | 기관 인증·내부 모델·운영 저장소, 근거·권한·오류·부하·복구 검증 | 외부 통신 차단 상태에서 핵심 흐름 완수, 다른 기관 환경에 공통 코드 적용 가능 여부 확인 |

단계 0의 업무 협의와 기관 내부망 환경 확인은 개발과 병행한다. PDF, DOCX, HWP, HWPX 중 대표 형식을 선정하고 표·스캔·페이지 위치 추출을 검증한다. 비동기 실행·결과물을 우선 구현해 업무를 맡기고 결과를 검토하는 흐름을 확보한다.

## 평가 목표 초안

| 항목 | 초기 목표 |
| --- | --- |
| 업무 유용성 | 대상 직원의 유용한 결과 평가 80% 이상 |
| 근거 정확성 | 인용이 답변 내용을 실제로 뒷받침하는 비율 90% 이상 |
| 접근 통제 | 계정별 접근과 기관별 배포 경계 시험에서 유출 0건 |
| 업무 효과 | 선정 업무 평균 소요 시간 30% 이상 감소 |
| 운영 | 응답 시간·실패율·작업당 비용 측정 및 허용 범위 확정 |

목표값은 합의 전 제안이며 보장값이 아니다. 근거 없는 질문, 구버전·상충 문서, 권한 없는 문서, 문서 안의 악성 지시, 모델·검색 장애를 평가 세트에 포함한다.
