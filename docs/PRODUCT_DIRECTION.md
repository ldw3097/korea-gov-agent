# K-gov-agent 제품 방향

2026-11-21 (Asia/Seoul) 갱신. 공공부문 전체로 확장한 제품 방향이며 이후 설계·구현의 기준이다.

## 목표

중앙행정기관, 지방자치단체, 공공기관 등 공공부문 기관의 직원이 각 기관의 내부망에서 ChatGPT Work와 유사한 경험으로 업무를 맡기고, 진행에 개입하며, 결과물을 검토·수정·재사용하는 업무 공간을 만든다. 내부 문서 질의·비교·초안 작성은 첫 검증 사례다. 기관별 업무 도구 연동과 반복 업무로 확장한다.

사용자 경험의 유사성을 목표로 삼되, 세부 화면과 동작을 확인하지 않은 기능까지 동일하게 구현했다고 주장하지 않는다. 모델·도구·실행 환경은 기관별 조건에 맞춰 구성한다. 특정 모델 제공자나 클라우드가 없어도 핵심 업무 흐름을 운영할 수 있도록 설계한다.

## 참고 근거와 설계 제안의 구분

공식 문서에서 확인한 Work의 경험은 업무 위임, 파일·도구 활용, 진행 상황 확인, 중간 질문에 답하기, 방향 수정, 중요한 실행 승인, 검토 가능한 결과물이다. 데스크톱 문서는 프로젝트와 대화를 오가고 같은 작업 공간에서 파일을 검토하는 경험을 설명한다.

- [ChatGPT Work 시작하기](https://learn.chatgpt.com/docs/get-started-with-work)
- [ChatGPT 데스크톱 앱](https://learn.chatgpt.com/docs/app)

아래의 화면 구조, 데이터 모델, 구현 단계는 공공부문 내부 업무에 적용하기 위한 제품 설계다. 세부 UX는 실제 참고 화면과 기관 업무 흐름을 확인한 뒤 조정한다.

## 핵심 사용 흐름

1. 직원이 새 대화 또는 프로젝트에서 원하는 업무 결과를 자연어로 요청한다.
2. 필요한 파일·기관 내부 자료·업무 도구를 입력창에서 첨부하거나 선택한다.
3. 에이전트가 작업을 진행하며 현재 단계, 사용한 도구, 근거, 오류를 표시한다.
4. 직원은 실행 중에도 추가 자료를 주거나 방향을 수정하고, 질문에 답하거나 실행을 중지한다.
5. 결과물이 대화와 연결된 미리보기 영역에 나타난다. 출처와 결과 버전을 확인하고 수정 요청을 이어간다.
6. 직원은 결과물을 내려받거나 허용된 공간에 저장하고, 같은 프로젝트에서 후속 업무를 이어간다.

검증의 기본 단위는 질문 한 번의 정답률에 더해 위 흐름 전체의 완수 여부다.

## UX 기준

| 영역 | 우리 제품의 목표 동작 |
| --- | --- |
| 왼쪽 탐색 | 새 대화, 최근 대화·작업, 검색, 프로젝트와 고정 항목으로 맥락 전환 |
| 중앙 작업 영역 | 대화 입력과 에이전트 진행 기록을 중심으로 구성 |
| 입력창 | 여러 줄 입력, 첨부 파일, 사용 가능한 내부 도구 선택. 지원하지 않는 도구는 실행 가능한 것처럼 노출하지 않음 |
| 실행 표시 | 대기·진행·입력 필요·승인 필요·완료·실패·취소를 명확히 구분 |
| 중간 개입 | 추가 메시지·질문 응답·방향 수정·중지. 처리 중인 도구를 즉시 끊지 못하는 경우 상태를 정확히 표시 |
| 오른쪽 결과 영역 | 문서·표·차트·파일 미리보기, 근거, 버전, 다운로드. 필요할 때 열고 닫기 |
| 프로젝트 | 관련 대화·자료·작업 지침을 묶고 후속 작업에서 재사용 |
| 작업 연결 | 브라우저를 닫아도 서버 작업 유지, 재접속 시 진행·최종 결과 복원 |
| 연동 | 기관 내부 자료·업무시스템을 도구로 연결하고 선택한 도구와 접근 범위를 표시 |
| 반복 업무 | 예약·정기 실행·변경 감지와 결과 알림을 후속 구현 |

Rust 브랜치는 서버 헬스체크에서 시작한다. 이 문서의 UX는 구현 목표다. PoC는 Google 로그인과 관리자 사용 승인으로 시작하고 사전 사용자 지정·부서 배정을 요구하지 않는다. 계정별 대화·파일 격리를 유지하며 [인증·승인 기준](AUTH.md)을 따른다.

## 실제 실행을 위한 기반

- 대화와 실행을 분리한다. 하나의 대화에 여러 실행·도구 호출·결과 버전을 연결한다.
- worker와 영속 이벤트로 브라우저 연결과 작업 수명을 분리한다. SSE 등 전송 방식과 관계없이 서버 상태가 기준이다.
- 실행 ID·메시지 ID로 재전송을 구분한다. 부작용이 있는 도구는 중복 실행과 완료 여부가 불명확한 중단을 별도로 처리한다.
- 진행 표시는 실제 실행 이벤트에서 만든다. 허구의 작업 단계나 모델의 비공개 추론을 진행 기록으로 표시하지 않는다.
- 파일 생성·분석은 사용자/실행별로 격리한 작업 공간에서 수행하고, 완료된 결과물과 버전을 소유자·공유 권한에 연결한다.
- 권한은 검색·도구·파일 다운로드·미리보기·프로젝트 공유·캐시마다 서버에서 검사한다. 프로젝트 생성으로 부서 전체 공유가 자동 활성화되지 않도록 한다.
- 승인 상태는 실제 실행·도구 인자·승인자에 연결한다. 승인 후 변경된 요청에 이전 승인을 재사용하지 않는다.

## 기관별 배포와 내부망 기준

기관별 독립 배포를 기본으로 삼는다. 대화·첨부·결과물·검색 색인·감사 기록은 각 기관의 배포 경계 안에서 관리한다. 공통 코드를 사용하고 인증·조직 정보, 추론·임베딩 모델, 저장소, 업무시스템 연동은 기관별 설정과 어댑터로 교체할 수 있게 설계한다.

내부망에서 인증, 모델 추론·임베딩, 검색, 문서 처리, 파일 생성·저장, 작업 큐를 운영할 수 있어야 한다. 기본 동작이 외부 CDN·웹폰트·검색 API·텔레메트리·클라우드 인증에 의존하지 않게 한다. 외부 통신은 해당 기관이 허용한 범위에서 명시적으로 설정한다.

파일럿에서는 기관의 망 구성, 인증 체계, 자료 접근 범위, 감사·보관 기준을 확인한다. 오프라인 패키지·컨테이너 반입과 외부 통신 차단 상태의 핵심 업무 흐름을 검증한다. 현재 OCI·Cloudflare Access·DeepInfra는 개발 시연에 사용한다.

## 구현 우선순위

| 단계 | 구현 내용 | 완료 기준 |
| --- | --- | --- |
| 1. Work 화면과 실제 대화 | 탐색·중앙 대화·결과 패널의 UI 기반, 모델 어댑터와 스트리밍 연결 | 실제 답변·중지·오류 표시, 기존 권한 격리 유지 |
| 2. 작업 수명과 결과물 | worker, 이벤트 재구독, 첨부 파일 분석, 첫 문서 결과물, 미리보기·다운로드 | 파일을 주고 작업을 맡겨 결과를 받으며 재접속 후 복원 |
| 3. 개입과 수정 | 실행 중 메시지, 질문 응답, 승인·취소, 결과물 후속 수정·버전 | 같은 대화에서 방향을 바꾸고 수정된 결과 확인 |
| 4. 프로젝트·기관 내부 지식 | 프로젝트 맥락·자료, 문서 검색·근거·권한 연동 | 프로젝트 간 전환과 권한 있는 기관 자료 활용 |
| 5. 업무 도구·반복 작업 | 내부 시스템 연결, 관리 가능한 도구 권한, 예약·알림 | 선정 업무의 여러 도구 연계와 반복 실행 검증 |
| 6. 기관 내부망 파일럿 | 기관 인증, 내부 모델·저장소, 운영 DB·마이그레이션, 배포·복구·부하 검증 | 외부 통신을 차단한 기관 환경에서 핵심 업무를 완수하고, 다른 기관 환경에도 공통 코드로 적용 가능한지 확인 |

단계는 개발 우선순위이며 보안·접근 통제는 각 단계에 적용한다. 기관별 어댑터 설계와 환경 확인은 초기부터 병행한다. 완성되지 않은 기능은 UI 연결과 실제 실행 완료를 구분해서 보고한다. 사용자가 별도로 요청하지 않은 데스크톱 전체 제어·직원 PC 접근 권한을 제품 유사성을 이유로 자동 부여하지 않는다.
