# K-gov-agent 구현 상태

시연 배포 기록 기준일은 2026-11-15 (Asia/Seoul)이다. 제품 방향은 2026-11-21에 공공부문 전체로 확장했다.

## Work 첫 버전 배포

- Work 형태 UI, 프로젝트·지침·자료 연결, 실제 DeepInfra 스트리밍, 영속 작업 큐와 진행 이벤트 구현.
- 실행 중 텍스트 추가 요청·중지, 질문 대기·응답 후 재개, Markdown 문서 생성·버전·미리보기·다운로드 구현.
- 전체 테스트 **67개 통과**. 실제 DeepInfra로 합성 프로젝트·첨부 분석·문서 생성·미리보기 API·다운로드 통과.
- 로컬 브라우저의 합성 계정으로 프로젝트 생성·작업·결과 패널·재접속 복원 확인.
- 기존 API/UI 버전은 보관하고 DB 스냅샷 후 배포했다. 인증·사용 승인과 개인 데이터 격리를 유지했다.
- 사용자 허용에 따라 기존 DeepInfra 키만 연결했다. 개인 대화·기억은 가져오지 않았다.
- PDF·한글/OCR·오피스 결과물·사내 시스템 도구·예약 실행은 후속이다. 상세 범위는 [WORK.md](WORK.md).

## 최신 PoC 인증: Cloudflare Google + 앱 사용 승인 (배포 완료)

- Cloudflare의 전용 Google IdP를 생성하고 해당 앱을 Google-only Allow 정책으로 전환했다. Bypass 없음, audience·Tunnel Protect with Access 유지.
- 앱은 Access JWT를 검증하고 issuer+subject로 계정을 자동 등록한다. 신규 사용자는 pending이며 최초 관리자만 자동 승인한다.
- 승인·거절·승인 취소는 매 업무 API에서 검사한다. 유효한 Access JWT가 있어도 거절된 계정은 차단한다.
- 앱의 직접 Google OAuth 비밀값은 환경설정에서 제거했다. 관리 API 토큰은 로컬 비공개 파일로만 사용했다.
- 전체 테스트 **49개 통과**, JavaScript 문법 검사 통과. 새 앱 health 200, 서명 없는 신원 401 확인.
- 외부 로그인 페이지의 Google OAuth 경로 확인. 사용자가 실제 Google 로그인 후 업무 화면 진입을 확인했다.
- 다른 실계정의 승인 대기·승인 취소는 합성 토큰 시험으로 검증했으며 실제 참여자 검증은 후속이다.
- 최신 인증 사양은 [AUTH.md](AUTH.md)를 따른다. 아래의 부서 공유·고정 허용 사용자 관련 설명은 이전 개발 기록이다.

## 초기 기반 구현 기록

- 새 프로젝트 구조와 계획·실행·설계 문서.
- 로컬 합성 계정 4개, 가상 부서 2개, 직원·관리자 역할.

- scrypt 비밀번호, 서버 세션, 로그인·로그아웃·만료·세션 회전.
- 대화와 사용자 메시지의 소유자 접근 통제, 삭제 시 메시지 정리.
- 개인·부서 공유 파일의 목록·등록·다운로드, 등록자 전용 삭제.
- 관리자 계정 정지·활성화, 정지 시 세션 폐기, 감사 이벤트 조회.
- 동일 origin 웹 화면, 응답 no-store, CSRF·Host·업로드 용량 제한.
- 임시 DB와 합성 데이터 기반의 API 통합 시험.

## 검증

- 독립 Python 가상환경에서 `pytest -q`: **32개 통과**. Access 서명·클레임 변조/만료·역할·사용자 분리 추가 검증.
- `node --check apps/web/app.js`: 통과.
- `pip check`: 의존성 충돌 없음. 검증 버전은 루트 `requirements.lock`에 고정.
- `git diff --check`: 공백 오류 없음.
- 실제 로컬 브라우저: 직원 로그인 → 대화 생성 → 메시지 저장 → 로그아웃 시 화면 초기화 → 같은 부서 다른 직원 로그인 시 기존 대화가 보이지 않음 확인.
- 새 앱 인스턴스에서 기존 DB의 세션·대화·파일 유지, 세 직원의 동시 쓰기 검증.
- 외부 클라이언트 거부, 입력 검증 오류에서 비밀번호 미노출 검증.

브라우저 검증은 별도 임시 DB와 합성 계정으로 수행했다. 기본 개발 DB의 계정은 자동 생성하지 않았으므로 README의 seed 명령으로 비밀번호를 지정해야 한다.

Starlette TestClient에서 httpx 사용 중단 예정 경고 1건이 있다. 운영 부하, 기관 내부망, 실제 기관 인증 연동은 파일럿 검증 범위다.

## 원격 시연 배포

기존 OCI에 시연 PoC를 별도 프로젝트로 배포하고 기존 Access·Tunnel 주소를 재사용한다. 개인용 컨테이너·네트워크는 제거하고, 원본 DB 볼륨과 암호화 백업은 보존한다. 두 DB의 격리 복원 검증을 완료했다. 새 DB에는 개인 대화·기억이나 로컬 합성 계정이 없다.

새 컨테이너의 내부 health 200, 미인증 원본 요청 401, Access 공개키 연결, 새 Tunnel 등록, 외부 익명 루트·API의 로그인 302를 확인했다. 브라우저 로그인 후 검증은 자동 승인 검토가 Cloudflare 대시보드 접근 위험으로 차단했으며, 사용자가 직접 확인하기로 했다. [배포·복구 기록](DEPLOYMENT.md)을 참고한다.

현재는 로컬·원격 시연용 기반이며, 기관 내부망 파일럿 배포는 후속 범위다.

## 확정된 제품 방향

공공부문 기관이 각자의 내부망에서 업무 위임·진행 개입·결과물 검토를 할 수 있는 공통 업무 에이전트를 개발한다. 기관별 독립 배포와 인증·모델·저장소·업무시스템 교체를 설계 기준에 반영했다. 문서 형식 확대, 기관 내부 검색과 업무 연동, 외부 연결 없이 운영하는 파일럿 검증이 후속 범위다. [제품 방향](PRODUCT_DIRECTION.md) · [구현 계획](IMPLEMENTATION_PLAN.md)
