# Feature Specification: 텍스트로 대화하는 챗봇 웹페이지

**Feature Branch** `codex/rust-restart`  
**Created** 2026-11-21  
**Status** 초안  
**Input** 텍스트 챗봇 웹페이지에 Google 로그인과 관리자 사용 승인을 포함한다.

## User Scenarios & Testing

### User Story 1 - Google로 로그인하고 승인 상태 확인하기 (P1)

직원은 사전 등록 없이 웹페이지를 열어 Google로 로그인한다. 처음 방문하면 승인 대기 안내를 받고, 이후 같은 계정으로 돌아와 처리 결과를 확인한다.

**Independent Test** 등록 이력이 없는 직원으로 처음 로그인한 뒤 로그아웃하고 같은 계정으로 다시 로그인한다.

**Acceptance Scenarios**

1. 로그인하지 않은 직원이 채팅 주소를 열면 Google 로그인으로 안내된다. 로그인을 취소하거나 신원 확인이 실패하면 계정이 생성되지 않고 대화도 열리지 않는다.
2. 직원의 첫 로그인에 성공하면 승인 대기 계정 하나가 생성된다. 직원은 본인 상태를 확인하고 로그아웃할 수 있다. 다시 로그인해도 같은 상태가 유지되고 관리자 목록에 계정이 중복되지 않는다.
3. 로그아웃한 뒤 기존 대화 주소를 다시 열면 로그인 절차를 거쳐야 한다.

### User Story 2 - 관리자가 사용 신청을 처리하기 (P1)

관리자는 승인 대기 목록에서 신청자의 이메일과 상태를 확인하고 사용을 승인하거나 거절한다. 이미 승인한 계정의 사용 권한도 취소할 수 있다.

**Independent Test** 초기 관리자로 로그인해 대기 중인 직원 한 명을 승인한다. 직원이 채팅을 시작한 뒤 관리자가 승인을 취소하고 같은 직원 세션에서 후속 질문을 보낸다.

**Acceptance Scenarios**

1. 설정에 지정된 최초 관리자는 첫 로그인부터 승인 관리 화면을 사용할 수 있다. 일반 직원이 먼저 가입해도 관리자 권한은 부여되지 않는다.
2. 관리자가 승인하면 직원은 대기 화면을 새로고침한 뒤 같은 계정으로 채팅을 시작할 수 있다. 신청을 거절하면 직원에게 거절 상태가 표시되고 채팅은 차단된다.
3. 관리자가 승인을 취소하면 직원의 기존 로그인 상태에서도 다음 대화 열기와 전송이 차단된다. 다시 로그인해도 취소된 권한은 복구되지 않는다.
4. 일반 직원이 승인 관리 주소로 직접 접근하거나 승인 처리를 시도하면 목록 열람과 상태 변경이 모두 차단된다. 관리자도 다른 직원의 대화 내용은 열람할 수 없다.

### User Story 3 - 질문하고 답변받기 (P1)

기관 직원은 웹페이지를 열고 텍스트로 질문한다. 같은 화면에서 자신의 질문과 챗봇의 답변을 차례로 읽는다.

**Independent Test** 승인된 계정으로 빈 대화를 열어 “회의 시작을 알리는 문장을 한 줄 써 줘”라고 보내고, 요청에 맞는 답변이 도착하는지 확인한다.

**Acceptance Scenarios**

1. 직원이 대화 화면을 처음 열면 입력란과 전송 동작을 바로 찾을 수 있다. 한글 질문을 보내면 보낸 글이 한 번 표시되고 답변을 기다리는 상태가 보인다.
2. 챗봇이 답변을 생성하면 같은 화면에서 도착한 부분부터 읽을 수 있다. 답변이 끝나면 질문과 답변의 작성자를 구별할 수 있고 다음 질문을 보낼 수 있다.

### User Story 4 - 앞선 대화를 이어가기 (P1)

직원은 같은 주제로 후속 요청을 할 때 배경을 반복해서 설명할 필요가 없다.

**Independent Test** “행사 이름은 솔바람이야”라고 알리고 답변을 받은 뒤, “그 이름을 넣어 환영 인사를 써 줘”라고 요청한다.

**Acceptance Scenarios**

1. 후속 요청에 대한 답변에는 앞서 알려 준 ‘솔바람’이 들어간다. 직원은 같은 화면에서 두 차례의 질문과 답변을 보낸 순서대로 읽을 수 있다.

### User Story 5 - 답변을 중지하거나 실패 후 계속하기 (P2)

직원은 너무 긴 답변을 중지하고 질문을 바꿀 수 있다. 응답이 실패했을 때도 앞선 대화에서 이어갈 수 있다.

**Independent Test** 긴 답변이 생성되는 도중 중지한다. 별도 대화에서는 응답을 받을 수 없는 상황을 재현한 후 연결을 복구하고 다시 질문한다.

**Acceptance Scenarios**

1. 답변 생성 중 중지를 선택하면 중지 상태가 표시된다. 이미 받은 글은 읽을 수 있고, 중지된 답변에 새 글이 붙지 않으며 다음 질문을 보낼 수 있다.
2. 답변 시작 전이나 생성 도중 실패하면 해당 질문에 실패 상태가 표시된다. 이전 대화와 이미 받은 글을 읽을 수 있고, 연결 복구 후 같은 화면에서 다시 질문할 수 있다.

### Edge Cases

- 빈 입력이나 공백만 보내면 대화에 메시지가 추가되지 않는다.
- 같은 전송 동작을 연속해서 눌러도 질문과 답변은 한 쌍만 생긴다.
- 로그인 전이나 승인 대기 상태에서 대화에 접근하면 내용을 읽거나 질문을 보낼 수 없다. 대화 도중 승인이 취소되면 이후 읽기와 전송도 차단된다.
- 다른 승인 사용자가 대화 주소나 식별자를 알고 있어도 그 대화를 읽거나 이어갈 수 없다.

## Requirements

### Functional Requirements

- **FR-001** 승인된 직원은 대화 화면에서 텍스트를 입력하고 전송할 수 있어야 한다. 공백 입력과 중복 전송은 새 질문을 만들지 않아야 한다.
- **FR-002** 질문과 실제로 생성된 답변을 작성자별로 구분하고, 대화 순서대로 표시해야 한다.
- **FR-003** 답변 대기 중임을 알리고 생성된 부분부터 표시해야 한다. 답변을 끝까지 받은 경우에만 완료로 표시해야 한다.
- **FR-004** 같은 대화의 후속 질문에는 앞선 질문과 답변의 맥락을 반영해야 한다.
- **FR-005** 직원은 생성 중인 답변을 중지하고 같은 화면에서 다음 질문을 보낼 수 있어야 한다.
- **FR-006** 응답 실패와 사용자 중지를 구별해 표시하고, 두 경우 모두 이미 표시된 대화 내용을 유지해야 한다.
- **FR-007** 대화 읽기와 전송은 현재 사용 승인이 유효한 소유자에게만 허용해야 한다.
- **FR-008** 웹페이지는 기존 Cloudflare Access의 Google 로그인을 사용하고, 앱은 이 서비스에 대해 확인된 유효한 신원으로만 계정을 등록하거나 접근을 허용해야 한다.
- **FR-009** 새 직원은 첫 로그인 때 승인 대기로 자동 등록해야 한다. 같은 신원으로 재방문하면 기존 계정과 승인 상태를 사용해야 한다. 미승인 직원이 사용할 수 있는 기능은 본인 상태 확인과 로그아웃으로 제한한다.
- **FR-010** 지정된 최초 관리자만 초기 승인된 관리자로 등록해야 한다. 일반 직원은 자신이나 다른 직원의 승인을 처리할 수 없어야 한다.
- **FR-011** 관리자는 신청자와 현재 상태를 확인하고 승인·거절·승인 취소를 처리할 수 있어야 한다. 변경된 상태는 다음 대화 접근부터 적용하며, 거절·취소·정지 상태에서는 채팅을 차단해야 한다.
- **FR-012** 직원은 대기 화면과 채팅 화면에서 로그아웃할 수 있어야 한다. 로그아웃 이후에는 다시 로그인해야 보호된 화면을 사용할 수 있다.

### Key Entities

- **계정** 확인된 로그인 신원에 연결된 직원 또는 관리자. 승인 상태는 로그인 이후에도 유지되며, 채팅 사용 권한을 결정한다.

- **대화** 한 직원이 같은 맥락에서 주고받은 메시지의 모음.
- **메시지** 직원이 보낸 질문 또는 챗봇이 생성한 답변. 작성자와 대화 내 순서가 있으며, 답변에는 진행 상태가 있다.

## Success Criteria

### Measurable Outcomes

- **SC-001** 승인된 직원이 빈 화면에서 첫 질문을 보내고 후속 질문까지 두 차례 대화를 마칠 수 있다. 화면에 질문 두 개와 실제 답변 두 개가 순서대로 남고, 후속 답변에는 처음 제공한 행사 이름이 들어간다.
- **SC-002** 긴 답변 한 건에서 직원이 완료 전에 일부 내용을 읽고 중지할 수 있다. 중지 후 한 번의 후속 질문으로 대화를 이어갈 수 있다.
- **SC-003** 답변 시작 전 실패와 일부 수신 후 실패 두 경우 모두 실패를 식별할 수 있다. 연결 복구 후 페이지를 다시 열지 않고 질문을 보내 답변을 받는다.
- **SC-004** 비로그인, 승인 대기, 승인 취소, 타인 계정의 네 경우 모두 대상 대화에서 메시지 읽기와 전송이 차단된다.
- **SC-005** 새 직원 한 명이 두 번 로그인해도 신청은 한 건이다. 관리자가 승인하면 직원은 대기 화면에서 채팅으로 이동해 첫 답변을 받는다. 로그아웃 후 대화 주소에 접근하면 다시 로그인을 요구한다.
- **SC-006** 대기 중 거절과 승인 후 취소를 각각 한 번 검증한다. 두 경우 모두 해당 직원의 다음 채팅 요청이 차단되고 재로그인 후에도 차단이 유지된다.
- **SC-007** 일반 직원의 승인 목록 조회와 승인 변경, 관리자의 타인 대화 열람을 각각 시도했을 때 세 시도 모두 차단된다.

## Assumptions

- 첫 버전에는 로그인, 관리자 승인 관리, 열린 페이지에서 나누는 한 대화가 포함된다. 대화 목록, 재접속 후 기록 복원, 파일 첨부, 문서 검색, 결과물 패널은 후속 범위다.
- 실제 사용 검증에는 기관이 허용한 대화 모델, 지정된 초기 관리자, 별도의 직원용 Google 계정이 필요하다. 로그인·관리자 승인과 계정별 격리는 프로젝트의 [인증 기준](../../docs/AUTH.md)을 따른다.
